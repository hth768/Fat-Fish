## 提交编码坑（本轮新增教训，补充到 git 提交规范）
- `i18n.commitEncoding` 在本机 **未设置**，git 用 `git commit -F <utf8文件>` 时把 UTF-8 字节按 GBK 误读 → 提交消息乱码（实测存储出双重 BOM + 锟斤拷式乱码）。
- 失败方法：`python -c "open('f','w',encoding='utf-8').write('中文…')"` —— PowerShell 会先把内联中文参数弄坏（PUA 字符 `\ue583`），写不出 GBK 也写不对 UTF-8。
- **可靠方法**：用工具(write_to_file)直接写出 UTF-8(无 BOM)消息文件，再 `git -c i18n.commitEncoding=utf-8 commit --amend -F <file>`。验证 `chcp 65001; git --no-pager log -1 --format=%B` 中文正常。
- 注：先前记忆写的「UTF-8 文件 + git commit -F 即可」在本机不成立（commitEncoding 未设），须带 `-c i18n.commitEncoding=utf-8` 才稳。
