## 根因（重要）：图片/外网下载全失败 = 本机死系统代理
- 用户换网后重发动图仍 `[ERROR] 图片获取失败: 无法获取图片`，且「所有网页都死」。**根因不是 NapCat**（已把 `E:\NapCat\napcat\config\onebot11_2174298281.json` 的 `enableLocalFile2Url` 改为 true，但无效）。

- 用户澄清「从没用过代理软件」→ 该死代理是软件残留，不应再开；关掉即恢复。务必把 `trust_env=False` 同步回仓库 `libs/qq_bot_runtime/qq_plugin.py`（当前仅改了运行实例 E:\qq_bot）。

## 修复：聊天不回话 + 记忆页失效（根因=孤儿 sidecar 端口 + WebView2 旧缓存 + App 桥接层滞后）

## 修复：调试控制台被「SSE 写入失败」刷屏（自我放大环）
- 现象（用户截图 16:31）：开启调试后控制台每秒刷几十条 `WARN SSE 写入失败 ConnectionAbortedError: [WinError 10053]...（server._sse_write）`，全是同一条。
- 根因：`server._sse_write` 把写异常**吞掉只记 degrade**，客户端断开后 SSE 写线程永不退出；之后每条广播（含调试事件本身）都发往死连接→写失败→degrade→quiet sink→`push_debug`→`push(None,{type:debug})` 广播→死连接再失败……**调试事件喂死连接再被吞再广播，指数级自我放大环**。旧 `push_debug` 无去重，同文本无限堆积。
- 修复（仓库 5 文件，已同步 E:\feiyu_app / D:\testing\Fat-Fish / E:\qq_bot + 重启验证）：
  1. `server.py._sse_write`：删 try/except，写失败**向上抛**→`_serve_sse` 外层捕获后退出 while 循环，finally 注销订阅队列（写线程首败即退）。外层 degrade「SSE 事件流断开（客户端可能已离开）」每条断开仅一次。
  2. `bridge/core_bridge.py.push`：加 `record: bool = True` 参数；`push_debug` 用 `record=False`，使调试事件**不进通用回放 `_log`**（防挤掉 recent(40) 里的真实事件 plugins_updated/error）。
  3. `push_debug`：连续同 level/text/where 且间隔 <15s 折叠为 ×N 计数（buf 记 `count`，SSE 带 `repeat`），断根后的残余重复告警也折叠。
  4. 前端 `webui/app.js.appendDebug`：收 `repeat` 事件只更新最后一行 `.dcount` 徽标（`×N`）不新增行；回灌时 `count>1` 渲染徽标；`openDebugConsole` 改为每次打开重新 `loadDebug()` 拿回后端缓冲里的折叠计数。`webui/styles.css` 加 `.dcount` 样式。
- 验证（阻塞式 curl 连 `/api/events` 2s 强断模拟死客户端，等 13s 心跳）：`SSE 写入失败` 行数 = **0**，断开只留 **1** 条「事件流断开」，日志共 16 条（含心跳）。`py_compile`+`node --check`+`python -m unittest discover -s tests`（59 个全过）。
- 教训（更新 MEMORY.md §2）：①**SSE 写失败必须向上抛**，吞异常会让死连接写线程存活并喂调试事件形成刷屏环；②调试事件别进通用回放历史；③远程调试/重连产生的断开告警应折叠。
