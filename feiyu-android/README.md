# 肥鱼娘 · 安卓版（Feiyu Android）

把 Feiyu 飞鱼框架的**主包 + 最基础聊天核心**移植到安卓手机的应用。

技术路线：**Kotlin + Jetpack Compose 原生 App**，聊天核心（人设 + 会话历史 + 调用大模型）在手机端直接运行，
直连 DeepSeek / Gemini / GLM / OpenAI 兼容的 `/chat/completions` 接口。
额外附带**本地向量记忆**：用 TF-IDF 离线向量做语义检索（无需额外接口即可工作），也可配置远程 embedding 端点增强效果。

## 功能

- **气泡式聊天界面**（Material 3 + Compose，minSdk 26 / Android 8.0+）
- **流式回复**（SSE 逐字显示，无限容量缓冲，不丢字）
- **图片识别**：可从相册发送图片（图文皆可），上传前自动压缩，使用 OpenAI 多模态规范格式
- **语音播报**：系统 TTS（免费离线）或云端 TTS；可调语速/音调/音色；支持分句停顿与情感参数
- **角色人设完全可自定义**：角色名 + 五个字段，App 不绑定任何具体角色
  - 内置 4 套预设模板：肥鱼娘（DeepSeek娘）/ 通用助手 / 学习伙伴 / 树洞
  - 可一键「清空」从零自定义；改动任一字段自动转为「自定义」
- **本地会话历史**（持久化到内部存储）
- **本地向量记忆**（详见下文）
- **设置页**：供应商、API Key、模型、温度、角色人设、记忆与摘要参数、embedding 配置
- **记忆页**：分类统计、查看 / 删除记忆、显示类型标签与命中次数

### 滚动窗口与摘要

- 每次只把**最近 N 轮**对话发给模型（默认 12 轮），避免历史无限增长导致 token 爆炸
- 超出窗口的旧对话会**自动用大模型压缩成摘要记忆**，保证长期连贯性
- 中断的回复**不会**写入历史与记忆，避免污染

### 记忆去重与淘汰

- 新记忆与已有记忆相似度 ≥ 阈值（默认 0.95）时**合并**而非新增，避免重复稀释检索质量
- 记忆条数超过上限（默认 800）时，按重要性淘汰：
  `重要性 = 类型权重(摘要2.0/画像2.5/对话1.0) × (1 + 命中次数×0.5) × 新鲜度(30天半衰)`
- **摘要类记忆永久保留**，不会被淘汰

## 配置大模型

首次打开 App → 右上角「设置」：

- **供应商**：选 `deepseek` / `gemini` / `glm` / `openai`，会自动填充 base_url；也可选「自定义」
- **API Key**：填入对应平台申请的 Key
- **模型名**：默认 `deepseek-flash`；也可填 `gemini-1.5-flash`、`glm-4-flash`、`gpt-4o-mini` 等
- **温度**：0 ~ 2，越高越随机

### 配置图片识别

设置页「图片识别」区块：

- **启用发送图片**：开关控制聊天页是否显示图片按钮
- **视觉模型名**：默认与主模型相同（`deepseek-flash`）。若某模型不支持视觉输入，
  可在此单独填一个支持视觉的模型（需与 API 地址 / Key 同属一家服务商）

### 配置角色人设

设置页「角色人设」区块：

1. **角色名**：显示在标题栏、打字提示、欢迎语、记忆来源标注中
2. **套用预设模板**：下拉选择内置预设，或选「清空（从零自定义）」
3. **五个字段**：身份 / 性格 / 能力 / 习惯 / 其他 —— 随意填写，想写成什么角色都行

## 向量记忆说明

每条用户/助手消息会被切分并向量化存储：

- **默认（离线）**：**TF-IDF 特征哈希**（512 维）+ 余弦相似度检索，完全本地、免费、无需额外接口
- **增强**：在设置里填「Embedding 端点 / Key / 模型」（OpenAI 兼容 `/embeddings`），改用真实语义向量，效果更佳

检索到的相关记忆会以「【相关记忆】」段落注入系统提示，让对话更具连续性与个性化。

## 从源码构建

1. 安装 **Android Studio**（Hedgehog 或更新）
2. 用 Android Studio 打开本目录 `feiyu-android/`
3. 连接手机（开启 USB 调试）或创建模拟器（**API 26+**）
4. 构建：
   ```bash
   gradlew.bat assembleDebug        # Windows
   ./gradlew assembleDebug          # macOS / Linux
   ```
   或直接双击工程根目录的 **`build-apk.bat`**（Windows 一键出包）
5. 产物：`app/build/outputs/apk/debug/app-debug.apk`

> 首次构建需要联网下载 Gradle 与依赖。
> 工程已配置国内镜像（阿里云 Maven + 腾讯 Gradle 分发）以加速下载。
> 本机无需 Python 运行时。

  - **云端语音**：走 OpenAI 兼容的 `/audio/speech` 接口，音质更好，需联网与 API Key
- **文本清洗**：朗读前自动去掉 markdown 标记、代码块、颜文字；代码块读作「（代码略）」
- **语音编辑**：
  - 语速 0.5x ~ 2.0x 无级调节
  - 音调 0.5 ~ 2.0 无级调节（系统引擎支持；云端接口无此参数）
  - 音色可下拉选预设或直接输入（alloy / echo / fable / onyx / nova / shimmer）
  - 试听按钮，调完立即听效果

- **朗读前改写稿件**（可选开关）：用大模型把回复改写成口语化、带停顿的版本；每次朗读多消耗一次模型调用

> **说明**：情感语气仅云端语音支持。手机系统 TTS 接口只能调语速与音调，无法控制情感。

### v1.0.3

**新增图片识别功能，默认模型切换为 `deepseek-flash`**

- **发送图片**：输入框左侧新增图片按钮，打开系统相册选择；选完可在输入框上方预览，可随时移除

- **模型变更**：默认模型 `deepseek-chat` → **`deepseek-flash`**，视觉模型默认同样为 `deepseek-flash`；

### v1.0.2

**彻底修复流式回复被截断的问题**

v1.0.1 的修复不彻底（只处理了发射端缓冲），本次定位到真正的根因：

- **读取循环提前退出（主因）**：原先用 `while (!source.exhausted())` 作为循环条件。
  `exhausted()` 是非阻塞探测，其语义是「当前缓冲区为空**且**源已到末尾」——在网络流中，
  socket 缓冲区**暂时没有数据**（但连接仍存活、模型仍在生成）时它也可能返回 `true`，
  导致循环提前退出、后续内容全部丢失。
  改为直接读行直到 `readUtf8Line()` 返回 `null`（真正的 EOF）。
- **超时过短导致连接被掐断**：OkHttp 默认 `readTimeout` 仅 10 秒，流式响应中模型若「思考」
  停顿超过 10 秒（排队、推理型模型、长回复间隙）会被静默掐断。
  已调整为 `connectTimeout 30s` / `readTimeout 5min` / `writeTimeout 30s` / `callTimeout 10min`。
- **增强可观测性**：增加 `Accept: text/event-stream` 头；分片解析失败输出日志；
  记录 `finish_reason`（若为 `length` 表示达到输出长度上限，属正常截断而非 bug）。

### v1.0.1

> ⚠️ 此版本截断修复不彻底，建议使用 v1.0.2。

**修复：流式回复被截断 / 展示不完整（不彻底，已被 v1.0.2 取代）**

- **修复丢字**：流式通道改为无限容量缓冲。原先 `callbackFlow` 默认缓冲仅 64，而回调运行在
  OkHttp 网络线程（非挂起），模型吐字快时 `trySend` 会**静默失败**，导致中间内容被丢弃
- **中断时保留已收内容**：网络中断不再清空半截回复，改为保留内容并在末尾追加中断提示；
  中断内容不写入历史与记忆
- **修复流式结束后文本回退**：移除 `finally` 中用旧状态回写文本的逻辑
- **长回复滚动跟随**：流式吐字过程中视图持续贴底（原先只监听消息条数，长回复会滚不上来）
- **消息气泡优化**：限宽 320dp、支持长按复制、行高优化，长回复完整展示不被裁切
