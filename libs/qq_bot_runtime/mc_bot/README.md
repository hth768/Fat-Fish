# mc_bot —— Mineflayer 纯净版试验场

给 LLM 大脑一个**原版世界**里的流畅身体（真寻路/原生挖掘/原生合成），
用于在无 mod 的纯净 LAN 世界试验，不受模组协议限制。

## 准备

1. 电脑要有 Node.js（本项目已用 v24 验证）。
2. 首次运行先装依赖（已装过可跳过）：
   ```
   cd mc_bot && npm install
   ```

## 启动步骤

1. 用**纯净原版**（无 mod 的版本/实例）开一个世界；
2. 游戏内 Esc → **对局域网开放** → 记下聊天里显示的端口（如 12345，临时端口每次不同）；
3. 启动桥：
   ```
   cd mc_bot
   MC_HOST=127.0.0.1 MC_PORT=25565 MC_USER=feiyu_bot node bridge.js
   ```
   （把 25565 换成第 2 步看到的端口）
4. 桥打印 `feiyu_bot 已进入世界` 后即可用：

   - 看状态:  curl http://127.0.0.1:8767/state
   - 走过去:  curl -X POST http://127.0.0.1:8767/cmd -H "Content-Type: application/json" -d '{"action":"goto","x":100,"z":-50}'
   - 挖木头:  curl -X POST ... -d '{"action":"dig","target":"oak_log"}'
   - 说话:    curl -X POST ... -d '{"action":"say","text":"你好"}'

## 说明与限制

- **auth: offline**：局域网联机默认离线模式，机器人可直接加入；主机若开了正版验证需调整。
- **自保反射 + 看门狗（不经 LLM）**：桥里 250ms tick 的反射层——头被埋立即挖、
  落入岩浆自动弃目标朝最近安全方向爬出、氧气不足抬头浮水、血量≤6 自动进食；
  反射事件进 `/state` 的 `reflexes` 流，大脑观察增量注入"⚠ 自保反射"行。
  `goto` 带 120s 看门狗，超时撤目标报错，防止大脑放弃后寻路还在背后跑。
- **只读一轮一答**：`scan`/`check_recipes` 同参重复调用在同一轮内直接回缓存
  （"本轮已读过，别再重复调"），治 LLM 轮询式重复扫描。
- **save_skill 校验带精确步序**：无效步骤回执精确到"第N步 xx（不是本环境工具）"，
  LLM 拿着回执一轮自纠。
- **阶梯式下挖找矿（dig_stairs）**：主人教的找矿法——不必死找矿洞。朝一个方向斜着往下挖台阶
  （每步先破面前墙、再下踏一格），每步暴露一整圈新方块面，比找洞入口更容易稳定露头。
  严格安全：挖踏步前先探测下方，见岩浆/水/深空腔即停并报告；每 3 步自动补火把，落地顺手捡掉落物，
  结束回报"下到几格、挖开什么、露出哪些矿（坐标）"。见 [bridge.js](bridge.js) `doDigStairs`。
- **不隔墙挖（视线校验）**：mineflayer 的 `bot.dig` 本身不查遮挡，服务器也不拦（会隔墙挖出后面的矿）。
  桥里 `dig`/`dig_at` 现在都先用 `bot.canSeeBlock`（射线检测）确认目标有面暴露、不被遮挡才挖；
  目标被挡时 fail 消息会提示"先挖开挡路的方块"，`dig` 会自动改试下一个可见的同名目标。
- **版本自动协商**：mineflayer 用 `version:false` 自动探测服务器协议版本。
- 这是"另一个玩家"的身体，有自己的背包/出生点，与主机角色互不干扰。
- 桥只暴露动作层；LLM 大脑在 `mc_bot_brain.py`（`python mc_bot_run.py` 启动），
  观察走 /state、动作走 /cmd，共用 Python 侧的记忆/技巧/技能资产。
- **原版学到、模组版应用**：大脑在原版摸索出验证有效的做法时调用 save_skill——
  ① 存成 bot 环境技能（带 env 标签，原版自己可用 run_skill 重放）；
  ② 自动把「场景→做法」沉淀成一条纯文字技巧进共享技巧库（mc_tips，learned 来源），
  FeiyuAPI 模组版大脑每轮注入"相关经验"时就能看到并用它自己的工具执行。
  技能步骤与模组技能互不污染：匹配/重放按 env 过滤，跨环境技能只提示参考做法，不会硬跑。
- **设施账本（重启也记得）**：桥自动记录自己放的方块、打开过的箱子内容快照、
  熔炉烧制任务，落盘 `mc_bot/ledger.json`（按 spawn 点分世界、再按维度分桶；
  换世界/换存档自动分桶）。`/state` 的 `facilities` 字段带出摘要，
  大脑观察的"我的设施"行每轮注入——重启/断线后仍知道"箱子在哪、里面存了什么、
  熔炉在烧什么"。快照只是索引，内容以游戏世界为准（走近重开窗口即实时）。
  注意：`container list` 的"箱内"此前误取了玩家背包区，已改为容器格（containerItems）。
- **地标按世界分桶**：「记住地点」现在带世界标记存储（原版=vanilla@维度，
  模组版按世界种子@维度），互不污染；老的无标记地标各世界都可见，确定废弃可删除；
  remember_place 发现同世界已有同名地标会提醒，避免"一堆家"。

## 模组世界（FeiyuAPI 模组）

模组版 MC 功能（模组世界）依赖一个**自建的 FeiyuAPI 模组**，这是模组世界的必须插件。
大脑通过它暴露的本地接口读取玩家/世界实时状态、下发指令；没有它时聊天会提示
「游戏没开或 FeiyuAPI 模组没加载」。

- **模组文件**：`feiyuapi-1.0.0.jar`（NeoForge 1.21.1）。
- **已随本包附带**：`mc_pack/mods/feiyuapi-1.0.0.jar`。把它放进游戏实例的 `mods/` 目录即可
  （游戏须为 NeoForge 1.21.1，且与模组编译版本一致）。
- **源码位置**：`mc_mod/feiyuapi/`（Gradle + `net.neoforged.moddev`；
  Minecraft `1.21.1` / NeoForge `21.1.248` / Java 21）。需要重新构建时：
  ```
  cd mc_mod/feiyuapi
  ./gradlew build        # 产物在 build/libs/feiyuapi-1.0.0.jar
  ```
- **版本要求**：NeoForge 1.21.1。模组版与纯净原版是两套不同的身体/协议，
  不要混用——模组世界用 FeiyuAPI 接口，原版用本 README 上面的 mineflayer 桥。
- 大脑在原版摸索出的技巧会通过共享技巧库沉淀，模组版每轮注入「相关经验」时复用，
  但技能步骤按 `env` 过滤，跨环境只提示做法、不会硬跑（见上文「原版学到、模组版应用」）。
