## 追加：修复流式回复被截断/展示不完整
用户反馈"智能体发消息时有时会被截断消息展示不完整"。定位出 3 个真实缺陷并全部修复：

1. **【主因】callbackFlow 缓冲溢出丢字**：`streamChatFlow` 用 callbackFlow（默认缓冲仅 64），
   而回调运行在 OkHttp 网络线程（非挂起），模型吐字快而 UI 消费稍慢时 `trySend` **静默失败** → 中间文字被丢。
   **修复**：流末尾加 `.buffer(Channel.UNLIMITED)`。
   （注意：`send()` 是挂起函数不能在 OkHttp 回调里用，`trySend` + UNLIMITED 才是正解；
   别试图手写 callbackFlowWithUnlimitedBuffer 包装，直接用官方 `.buffer()` 即可。）
2. **异常时已收内容被整体覆盖**：原来 catch 里直接 `updateAssistant(...,"（出错了：xxx）")` 把半截回复全丢了。
   **修复**：catch 内保留 `sb.toString()`，只在末尾追加「（回复中断了：xxx）」；且中断内容**不写入历史与向量记忆**
   （避免把错误提示污染成长期记忆）。
3. **finally 用当前 state 回写文本**，并发下可能把已渲染内容回退成早期版本。
   **修复**：finally 只置 `isSending=false`，正常结束才在 try 体外统一更新为完整文本。

## 【关键修复】截断问题真凶（2026-09-17）
用户反馈"输出还是会被截断"——即 v1.0.1 的修复**不彻底**。深挖后找到真正的根因（此前误判）：

### 真凶 1（主因）：`while (!source.exhausted())` 用法错误
`exhausted()` 是**非阻塞探测**：语义为"当前无缓冲数据且源已到末尾才返回 true"。
网络流中 socket 缓冲**暂时为空**但连接仍存活时，它也可能返回 true → **循环提前退出，后续内容全丢**。
→ 正解：`while (true) { val line = source.readUtf8Line() ?: break }`（null 才是真 EOF）。
**这是上次 `.buffer(UNLIMITED)` 没解决问题的原因**——丢字发生在更前面的读取环节。

### 真凶 2：OkHttp 默认 readTimeout 仅 10 秒
流式响应中模型"思考"停顿超 10 秒（排队/推理型模型/长回复间隙）会被静默掐断。
→ 正解：`connectTimeout 30s / readTimeout 5min / writeTimeout 30s / callTimeout 10min / retryOnConnectionFailure(true)`。

### 顺带加固
- 发 `Accept: text/event-stream` 头
- 分片解析失败时打 `Log.w` 日志（不再完全静默），便于定位
- 记录 `finish_reason`（`length` = 达到输出长度上限，属正常截断而非 bug）
- `trySend` 失败（下游关闭）才 break

## 【重要修复】相册选图在国产 ROM 上静默失败（2026-09-18）
用户反馈「装了新版但图片/语音按钮都没有」→ 排查过程与结论：

### 排查手段（有效，可复用）
1. **判断 APK 新旧的最可靠方法**：用 `aapt2 dump badging` 读 `application-label`：
   `E:\AndroidSDK\build-tools\35.0.1\aapt2.exe dump badging <apk>`
   （`resources.arsc` 里字符串是压缩/UTF-16 存的，findstr 直接搜**搜不到**，别浪费时间）
2. **验证代码是否编译进 APK**：解包后 `findstr /M /C:"关键字" classes*.dex`
   （搜设置键名字符串最有效，如 `vision_model`、`tts_pause_sentence`）
3. **Gradle 增量陷阱**：源码文件时间被外部改动（如 git checkout）后，
   `assembleDebug` 会全部 `UP-TO-DATE` 复用旧产物 → **必须先删 `app/build` 再构建**才能强制全量编译

### 根因 1：`Icons.Filled.Image` 图标渲染失败
`ChatScreen` 里图片按钮用 `Icons.Filled.Image`，在部分设备/主题下**静默不渲染**（不报错、就空白）。
**修复**：换成 `Icons.Filled.Image` 之外的稳定图标；诊断阶段用 `Icons.Filled.Add` 验证可用。

### 根因 2【关键】：`PickVisualMedia` 在国产 ROM 上点击无反应
`ActivityResultContracts.PickVisualMedia()` 依赖系统的 Photo Picker（Android 13+ 原生组件）
与 Google Play 服务。**国产 ROM（华为/小米/OPPO/vivo）多数没有，且无 GMS** →
`launch()` **静默失败**：不抛异常、不打开任何界面，表现为"点了没反应"。

**修复**：改用 `ActivityResultContracts.GetContent()`，它走系统传统文件选择器，
所有 Android 设备都支持：
```kotlin
val pickImage = rememberLauncherForActivityResult(
    contract = ActivityResultContracts.GetContent(),   // 不要用 PickVisualMedia
) { uri -> if (uri != null) vm.onImagePicked(uri) }
// 调用：
pickImage.launch("image/*")   // 传 MIME，不是 PickVisualMediaRequest
```
并包 try-catch，失败时 `vm.reportError(...)` 让用户看到提示。

## 【重要修复】点朗读没声音：TTS 引擎从未初始化（2026-09-18 13:11）
用户反馈「点播放没声」。根因是**架构缺陷**，不是环境问题：

### 根因
`TtsEngine` 接口定义了 `suspend fun isAvailable()` 用于触发**懒初始化**
（`SystemTtsEngine.ensureReady()` 会异步创建 `TextToSpeech` 并等待回调）。
但 **`isAvailable()` 只被定义、从未被调用**——`TtsController.speak()`/`preview()`
直接调 `engine.speak()`，此时 `tts == null || !ready` → 立即 `onError("系统语音尚未就绪")`，
**永远没声音**，且错误提示不明显，用户只感知到"点了没反应/没声"。

### 修复
1. `TtsController` 新增 `scope = CoroutineScope(SupervisorJob() + Dispatchers.Main)`
2. `speak()` / `preview()` 改为：先 `scope.launch { engine.isAvailable() }`，
   就绪后再 `playChunks()`；未就绪则给出**可操作**的提示
3. 新增 `unavailableHint(engine)`：系统语音提示去「手机设置 → 无障碍 → 文字转语音」检查；
   云端提示检查地址与 Key
4. `release()` 里 `scope.cancel()`
5. `SystemTtsEngine.speak()` 的错误文案也改为同样的可操作指引

### 教训
**定义了"初始化/可用性检查"接口，就必须在所有使用路径上真正调用它。**
懒初始化 + 异步回调的组合下，漏调用不会编译报错，只会在运行时静默失败。
凡是"点了没反应/没声音"类问题，优先检查：①依赖是否已初始化 ②是否只给了模糊错误 ③错误是否被吞掉。

## 【重要修复】TTS 初始化竞态（2026-09-18 13:27）
用户反馈"还是听不见"。深挖 `SystemTtsEngine.ensureReady()` 发现**第二个更隐蔽的 bug**：

```kotlin
// 有竞态的旧代码
val engine = TextToSpeech(context) { status ->
    engineSetChinese()     // ← 回调内访问 tts 字段，此时还是 null！
}
tts = engine               // ← 赋值在构造之后
```
`TextToSpeech` 构造回调在某些设备上**触发极快甚至同步**，
此时字段 `tts` 尚未赋值 → `engineSetChinese()` 里 `val engine = tts ?: return` 直接跳过
→ **语言没设成中文且不报错** → 引擎"可用"但发不出声。

**修复**：先用局部 `engineRef` 持有实例并同时赋给字段，
回调里用 `engineRef ?: tts`，不依赖字段时序；`engineSetChinese(engine)` 改为接收参数。
