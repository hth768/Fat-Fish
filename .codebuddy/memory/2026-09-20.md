## 新功能：聊天发送图片/视频/语音（提交见 git log）
- 前端 `webui/index.html` 聊天栏加工具栏（🖼️图片/🎬视频/🎤语音）+ 预览区；`app.js` 新增 pendingImages/pendingVideo/pendingAudio 状态、FileReader→dataURL 上传范式、`MediaRecorder` 录音转 dataURL、乐观渲染附件。`sendChat` 现在带 `images/video/audio`(base64 dataURL) POST。
- 后端 `server.py /api/chat`：接收 images(列表)/video/audio(dataURL) → 解码落盘 `data/media/<uuid>.<ext>`；语音 webm/ogg 经 `config.FFMPEG_PATH`(ffmpeg) 转 16k 单声道 wav（wav/mp3 直传）；`core_bridge.submit_chat` 扩展 `image_paths/video_path/audio_wav` 并构造 InboundMessage(image_refs/has_video/video_ref/audio_wav)。
- 关键缺口补丁：`bridge/core_bridge.py` 的 `AppReplyTarget` 原本**只实现 reply_*/tts，没有 fetch_image/fetch_video**，发媒体会 `NotImplementedError`（接收侧 chat_service 调用 `reply.fetch_image(ref)`/`reply.fetch_video(ref)`）。已补两方法读本地落盘文件。
- 能力依赖（环境/配置，非本代码）：图片/视频理解需要已配 vision 能力或本地模型（describe_video 支持本地优先/云端兜底，需 ffmpeg 抽帧）；语音输入依赖 `config.ENABLE_VOICE` + GLM ASR API（voice_client.speech_to_text，需联网/Key）。`AppReplyTarget.capabilities={"voice":False}` 仅关输出语音分支，不影响输入 ASR。
- 冒烟测试：POST 带 1x1 png → `{"ok":true}` 且 `data/media/img_*.png`(69B) 落盘，日志无异常。
