# 阶梯式下挖找矿(bridge 复合动作 dig_stairs)

## 背景
用户教了一招原版找矿技巧:"挖矿不一定要找矿洞,可以阶梯式下挖"。当前原版大脑只有 `dig_target`(按方块名找最近的挖),没有"往下挖开未知方块"的动作,想阶梯下挖只能瞎猜坐标。需要新增一个复合动作,并让这条经验跨环境传到模组版。

## 改动

### 1. mc_bot/bridge.js — 新增 `doDigStairs(direction, steps)`(核心)
- 注册到 dispatch:`if (a === 'dig_stairs') return await doDigStairs(cmd.direction, cmd.steps)`,steps 上限 8。
- 每步逻辑(方向向量复用 probe 的 dirVec 映射 north=[0,-1]…):
  - 站在脚层 fy:先挖面前同层方块 (fx+vx, fy, fz+vz)(墙),再挖其下方 (fx+vx, fy-1, fz+vz)(踏步下台阶);已是空气则跳过。
  - **安全(严格模式)**:挖下方格之前探测其下 1~3 格——正下方/下下方是岩浆或水则拒挖并报"下方岩浆/水,建议换方向或放火把查看";连续空腔>3 格(挖穿大洞)则停在该步报告,不往下跳。
  - 挖开后可见矿(`scanResources` 的 ore 名单)→ 记入"露出"列表。
  - 走到挖开的台阶上(pathfinder GoalNear 1 格内),`collect` 掉落物。
  - 每 3 步且背包有 torch 且附近有已挖开的墙脚:自动放火把照明(复用 doPlace 的 sneak 放置模式)。
- 返回 `{ok:true, msg:'阶梯下到 (x,y,z) 深N步, 挖开: stone x6/dirt x2, 露出: iron_ore x2 (可用 dig_target 挖)', exposed:[{name,x,y,z}]}`;被危险打断返回 ok:false+原因+当前坐标。
- 风格对齐现有代码:中文 msg、`_isAir/_isLavaWater/_bestToolFor/_digOne/_ledgerDigRemoved/_ensureReach` 复用、`bot.lookAt` + delay(300) 再挖。

### 2. mc_bot_brain.py — 注册工具 + 提示词
- `_t_dig_stairs(direction, steps)` handler(timeout 给足 ~300s)。
- `BOT_TOOLS` 增加 `dig_stairs` schema(direction enum、steps 1~8)。
- 系统提示词"交互/生存阶段"处补一句:找矿不一定要找矿洞——开阔地/山坡上 dig_stairs 阶梯下挖,露头就用 dig_target 收尾。
- 失败防重试白名单(1064 行 target 列表)补 `dig_stairs` 的 direction 参数。
- `_routine_suggest`:铁镐在手且背包缺铁/煤且在地表 → 提示 `dig_stairs`。

### 3. mc_tips.json — 沉淀这条主人经验(跨环境通道)
- `add_tip("找矿不一定非要去矿洞：露天山坡或基地旁直接阶梯式下挖——斜着往下挖台阶，每步都暴露新的方块面，比找洞入口更稳定地露头；挖穿见大空腔或闻到岩浆味就停", source="user")`(带"挖/矿/洞"关键词,两版大脑场景匹配都能命中,模组版用 look+mine_looking_at+move 自行执行)。

## 验证
- `node --check bridge.js`;`py_compile`。
- 用临时 ledger 文件跑 doDigStairs 纯逻辑单测不可行(依赖 bot),故以 node --check + dispatch 接线 + brain 导入冒烟为准;真机行为留给下次 LAN 测试观察。
- 确认 dig_stairs 走的是"先挖墙后踏步"顺序,不能隔墙直挖(与上轮 canSeeBlock 修复一致)。

## 不做
- 不往技能库存可重放序列(dig_stairs 是参数化动作不是序列);模组版无需代码改动,靠技巧文字迁移。
